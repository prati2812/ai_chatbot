AI Chatbot Architecture & API Flow

app/ — Modular Python Backend Architecture using FastAPI, Dependency Injection, and the Factory Pattern

App: ai_chatbot Architecture: Service Repository / Dependency Injection / Strategy Pattern Framework: FastAPI
30-second version: The application is split into distinct layers. The API endpoints (api/) never directly talk to the language models. They delegate to the ChatService, which uses a PromptBuilder to format the messages. The ChatService then delegates to an abstract AIProvider. At runtime, the ProviderFactory injects the specific implementation (e.g. Ollama, OpenAI) configured in the .env settings.

4. Dependency Injection & Factory Pattern

The Factory Pattern (factory.py) guarantees that nothing in the codebase needs to know whether the app is running Ollama, OpenAI, or Gemini, except for the factory itself. It reads the default_provider from the settings and instantiates the correct class.

The dependencies.py file leverages FastAPI's Depends() system to wire the application together. It acts as the composition root:

  • It calls the Factory to get the correct AIProvider instance.
  • It gets the singleton MemoryService.
  • It creates a PromptBuilder instance.
  • It injects all three into the ChatService.
  • It provides the fully assembled ChatService to the FastAPI route.

5. How to extend the App

Goal Action Required
Add a new AI provider (e.g., Anthropic) Create anthropic_provider.py implementing AIProvider. Add it to the PROVIDERS dictionary in factory.py. Update .env to use it.
Add a new persona/prompt Create a file in prompts/ (e.g., therapist.py). Update prompt_builder.py to dynamically select the prompt based on an argument.
Persist memory to a Database Update memory_service.py to connect to SQLite/Redis instead of using the in-memory dict. The rest of the app will remain completely unaware of the change.

6. Recent Architectural Upgrades

The system recently underwent massive upgrades to support agentic capabilities, streaming, and tool execution while remaining fully provider-agnostic.

A. Context & Token Management

The TokenManager and ContextManager intercept the prompt before it hits the LLM. They compress chat history using sliding windows and ensure the final payload strictly adheres to the model's context limits (e.g., preventing token overflow errors).

B. Hybrid Tool Calling (ReAct vs Native)

Because some local models (like llama3) lack native JSON tool-calling, the architecture implements a dual-strategy approach controlled by USE_NATIVE_TOOLS.

  • Native Mode: OllamaProvider forwards the tool JSON schemas directly to the LLM and processes native tool-call streams.
  • ReAct Fallback Mode: PromptBuilder injects formatting instructions (@@TOOL_CALL@@) into the system prompt. The OutputParser parses these tags out of the raw text and converts them into the exact same payload structure, making the orchestrator completely oblivious to the LLM's limitations.

C. The 9-Step Tool Executor Pipeline

Tools are never executed blindly. The ToolExecutor runs a strict 9-step security and validation pipeline before executing any tool requested by the LLM:

  1. Apply Execution Limits (prevents infinite loops)
  2. Resolve Tool (via ToolFactory)
  3. Check Authorization (validates against a whitelist)
  4. Validate Arguments (using jsonschema)
  5. Apply Timeouts (via asyncio.wait_for)
  6. Execute Code
  7. Validate Result
  8. Normalize Result (returns standard JSON payloads for both success and errors)
  9. Return to LLM

D. Event-Driven Streaming

The StreamEvent dataclass decouples core business logic from HTTP implementations. The OllamaProvider yields StreamEvent chunks. The ChatService consumes them, quietly executes tools in the background, and seamlessly passes the text events up to the API layer, which transforms them into text/event-stream Server-Sent Events (SSE) for the user interface.

7. Unified Project Architecture

The culmination of these systems is a highly scalable, enterprise-ready AI architecture capable of orchestrating complex agentic workflows, securely interacting with external systems via MCP, and streaming responses to the user in real-time.
